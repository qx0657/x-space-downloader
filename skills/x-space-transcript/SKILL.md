# X Space 下载、转写与总结

代码在 `/Users/glow/dev/projects/x-space-downloader`（下文简称「仓库」）。三步串起来做，每一步的产物都留在磁盘上，失败时从失败的那一步重跑即可。

## 1. 下载录音和发言人时间线

```bash
node /Users/glow/dev/projects/x-space-downloader/tools/download.mjs "<Space 链接或 ID>"
```

- 默认保存到 `~/Downloads/X-Spaces/`，文件名是「日期 @主持人 标题」。用户指定位置时加 `--out-dir`。
- 进度打印在 stderr；成功后 stdout 最后一行是 JSON，`audio` 和 `speakers` 字段就是下一步要用的两个文件路径。
- 同名文件已存在会跳过下载；需要重下时加 `--force`。
- 只想看标题、时长、状态时用 `--info`。试跑可以加 `--max-segments 100`（约 5 分钟）。
- 只用游客身份，不读浏览器登录态。常见失败：
  - 「需要登录 / 无权访问」：受限 Space，请用户改用仓库里的 Chrome 扩展，在已登录的浏览器里下载。
  - 「回放还在生成」「正在直播」：直播结束后几分钟再试。
  - 429：被限流，等几分钟再试，不要连续重试。

## 2. 转写成带发言人的文字稿

```bash
uv run /Users/glow/dev/projects/x-space-downloader/tools/transcribe.py "<audio 路径>"
```

- 默认引擎 FunASR 中文模型，在 CPU 上跑：两小时录音大约 5 分钟。首次运行会下载约 1 GB 模型到 `~/AI-Services/models/modelscope`，需要多等一会儿。命令耗时长时放到后台，定期查看输出。
- 产物和录音放在一起：`<同名>.transcript.md`（给人和 AI 读）和 `<同名>.transcript.json`（每段带起止秒数、发言人 id/handle/name，以及逐字时间）。
- 每段文字归给当时麦克风音量最大的人。一两个字的归属偶尔会错，整段归属是可靠的。
- 英文为主的 Space 改用 Whisper：`uv run --with mlx-whisper .../transcribe.py "<audio>" --engine whisper`。
- 试跑只转开头：`--duration 600`。

### 术语表

专有名词（产品名、社区名、人名）容易听错，靠术语表机械替换来纠正：

- 全局术语表：`仓库/tools/glossary.txt`。只放这个领域通用、不会误伤的写法。
- 单场术语表：录音旁边的 `<同名>.glossary.txt`，格式相同，会自动合并。嘉宾名之类只属于这一场的写法放这里。
- 格式：`正确写法: 听错写法1, 听错写法2`；只写正确写法时只作为热词。

总结前先扫一遍文字稿，看到明显听错的专有名词时：把它们写进单场术语表，重跑第 2 步（模型已缓存，很快），再总结。如果是以后也会反复出现的通用词，告诉用户，由用户决定是否加进全局术语表。

## 3. 整理总结

读 `<同名>.transcript.md`。文字稿很长时分段读完再写，不要只读开头。写到录音旁边的 `<同名>.summary.md`，结构如下：

```markdown
# <Space 标题>

- 时间、主持人、发言人和各自的发言时长（取自文字稿开头）
- 链接

## 整场摘要

三到六句话概括这场在聊什么、得出了什么结论。

## 主要议题

按讨论顺序列出议题，每个议题写清楚要点和起始时间点 [hh:mm:ss]。

## 按发言人整理观点

每位发言人一个小节，标题用「昵称 (@handle)」。列出他的核心观点、给出的经验或数据，以及和别人不同的看法。

## 关键原话

5 到 15 条值得引用的原话：「原话」— 昵称 (@handle) [hh:mm:ss]。

## 提到的工具、链接和待办

- 工具 / 产品 / 项目：名称和一句话说明谁在什么语境下提到
- 链接：只列发言里明确说出的网址或账号，不要自己补全或猜测
- 待办 / 后续计划：谁说要做什么、什么时候
```

写作要求：

- 原话照抄文字稿，只允许去掉「呃」「就是」这类口头禅；时间点和发言人以文字稿为准。
- 开场前的试音、背景音乐、等人进场的闲聊不写进摘要。
- 文字稿里明显是识别错误、又不能确定原词的地方，在总结里标「（疑似识别错误：xxx）」，不要猜成别的词。
- 用户另有要求（只要摘要、换成英文、侧重某个话题）时按用户的来。

完成后告诉用户三个文件的位置：录音、文字稿、总结。另外说明这次新加或建议加的术语。
